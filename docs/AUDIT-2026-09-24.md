## Implemented

- **Atomic AI reservations.** Every text HTTP attempt reserves against its
  existing audit/brief/geocode daily cap, including fallback attempts, errors and
  timeouts. Embeddings reserve each outgoing chunk before sending, rather than
  counting successful vectors afterward. An unavailable ledger blocks requests.
  Conditional PostgreSQL upserts enforce the limit across processes without an
  interactive transaction or schema migration. Caps remain 270/50/145 and 900.
- **Atomic translation reservations.** Concurrent callers cannot both spend the
  same allowance: the write compares today's count with the count used for the
  monthly calculation. A conflict skips this attempt until a later cycle. The
  existing daily/hourly/per-call pacing and 490,000-byte ceiling stay in place.
  Translation pauses during the first eight UTC hours of a new month, covering
  a possible Pacific billing boundary without rewriting the historical UTC ledger.
- **Outage handling.** All models cooling down now means no more HTTP attempts.
  A review round with no answers exits instead of rereading the same backlog.
  Failed requests retain reservations because an upstream timeout is ambiguous.
- **Answer handling.** Briefs and geocoding now share the audit client's rule:
  join answer parts, exclude thought parts, and reject incomplete/blocked output.
- **Explainable country detail.** Each pillar exposes its exact already-computed
  weighted load. The panel displays load, shared threshold constants, method
  version and calculation time. It refreshes every 15 minutes while visible and
  labels failed refreshes while retaining the last successful result. A failed
  summary response no longer blanks the globe's existing risk colors.
- **Honest health alarm.** The daily source-publication check counts approved,
  visible arrivals; pending and rejected arrivals no longer mask a publication
  outage. It still measures arrival time, not an approval timestamp.

No score formula, classification policy, source integration, model promotion,
database schema, paid service, or schedule was added or changed. Scoring stays
at version 3. Exposing an existing load does not change its calculation. New
budget semantics are conservative: fallbacks can now consume the daily allowance
faster during outages. Pre-deploy counters are not an exact attempt ledger, and
old processes already running at rollout may still use the previous guards.

These limits constrain this application's requests. They cannot guarantee a
provider account's total consumption when keys are used elsewhere. Per-minute
pacing is still process-local; independent manual jobs can compete for provider
RPM. Neon compute, Vercel consumption, and provider token quotas are separate
limits and must not be described as covered by daily request counters.

## Next work, ordered by value

1. **A reproducible scoring receipt.** Persist the scored story IDs, exclusion
   reasons, source-family bonus, exposure, decay and instrument saturation at
   snapshot time. Today's country event list is only the latest 50 primary rows;
   its individual `weight` is severity × decay, not the full v3 contribution.
   It cannot be summed to reproduce the published score. Design compact retention
   before storing receipts; ride the existing snapshot job.
2. **Evidence coverage separate from impact.** `correlation_group_id` groups
   country/pillar/day, so diversity within it is not proof that several outlets
   confirmed the same incident. Replace story-level “cross-confirmed” claims with
   actual duplicate/incident evidence, and show missing coverage distinctly from
   low observed activity. Measure any effect before altering scoring.
3. **Forecast targets that users can verify.** Specify outcomes such as a new
   sustained High security episode or a measured transport disruption within a
   named horizon. Forecasting GeoPulse's own score mainly forecasts its intake
   and decay; it is not yet a calibrated probability of real-world country loss.
   Add source availability and missingness to the existing daily feature snapshot
   before training, so provider outages do not masquerade as de-escalation.
4. **Stricter evaluation before more complex ML.** Same-version input/outcome
   matching is already tested, but there is only one observed v3 date. Require
   temporal coverage, not merely many country rows from one day. Use purged
   rolling-origin evaluation, country/date-blocked uncertainty estimates,
   calibration for probabilistic outcomes, and persistence plus seasonal/count
   baselines. Compare a hierarchical count model and the existing ridge/boosted
   models only after sufficient same-method history exists. Keep shadow output
   and the human classifier promotion gate intact.
5. **Operational follow-up.** Confirm the final seven reviews clear, track the
   archive backlog's daily net change, and obtain actual Neon CU-hours before the
   October cadence change. The current cron definitions also leave September
   1–20 of future years uncovered; replace the temporary calendar trick before
   next September. A non-Google fallback remains an owner decision, with current
   terms, model IDs and account-specific free limits verified before integration.
