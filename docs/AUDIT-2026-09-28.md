## Neon and Vercel

Limits verified from the providers' own pages on 2026-09-28: Neon Free is 100
CU-hours a month, suspends after 5 idle minutes (not configurable on Free) and
suspends the database when the allowance runs out
([plans](https://neon.com/docs/introduction/plans)). Vercel Hobby includes 1M edge
requests, 1M invocations and 4 active-CPU hours a month, and pauses for up to 30
days when exceeded ([Hobby](https://vercel.com/docs/plans/hobby)).

Measured: the ingest, review and briefs chain keeps Neon busy 75-110 s per cycle;
the fixed 5 idle minutes dominate, so the number of separate wake-ups is the lever.

| Change | Why |
| --- | --- |
| `/api/anomalies` and the globe scores (`/api/risk/summary`) are ISR, regenerated by the pipeline's purge | Any open tab re-queried anomalies every 5-10 min (data changes daily) and scores every 15 min, waking Neon between pipeline runs |
| The runner requests each purged route right after purging | Regeneration happens while the database is already awake |
| Feed fallback 15 min → 1 h | A 15-minute timer regenerated the feed between 30-minute pipeline runs |
| Polls: feed 12 s → 60 s (hidden 60 s → 5 min), scores 60 s → 5 min, anomalies 5 → 30 min | Matched to how often each can change; about 5x fewer edge requests per open tab |
| Daily Vercel ingest cron stands down if an ingest succeeded in the last 90 min | It duplicated the GitHub run on metered CPU every day (detected by the documented `x-vercel-cron-schedule` header) |

Not changed, on purpose: forex and commodity market rows are live Yahoo intraday
quotes, so their 60-second refresh stays. Neon compute and Vercel usage were not
readable from here (no CLI credentials), so the savings above are reasoned from
code and measured job timings, not from the providers' meters.

## Gemini

48 pipeline runs (2026-09-27 06:40 to 2026-09-28 06:05 UTC): 9 primary-model
failovers, all answered by a fallback model; one embedding 503; zero rounds with
every model unavailable. Errors are not currently losing reviews.

Daily usage against the owner's caps (2026-09-18..27): audit ~100 of 270, briefs
50 of 50 (by design), geocode ~36 of 145, **embeddings ~888 of 900 every day**.
The embedding budget is the binding constraint: 9,101 of 34,983
classification-archive rows are embedded.

Checked and rejected: reusing feed-archive vectors for the classifier archive
(same stories). Only 266 of 7,603 pairs have identical text, and the stored vectors
for the same story have median cosine 0.91-0.94 (5th percentile 0.84), so reuse
would change the training data.

Open question for the owner: whether `batchEmbedContents` counts one request per
batch or one per text. Google's docs do not say
([rate limits](https://ai.google.dev/gemini-api/docs/rate-limits),
[embeddings API](https://ai.google.dev/api/embeddings)), and the only public
report ([python-genai #427](https://github.com/googleapis/python-genai/issues/427))
is unresolved. The project's AI Studio rate-limit page shows the real numbers. If
a batch counts once, embedding throughput could rise many times over within the
same quota.

## The gate student (a learning loop that needs no API calls)

`src/lib/gateStudent.ts`: hashed words and word pairs, source and category, into a
logistic regression trained on the review gate's own decisions (gate reasoning,
audit rejections and human grades; auto-promotions and withheld items excluded).
Retrained inside the daily audit job, recorded on /models beside its baseline.

First run, trained on 1,348 decisions, scored on the newest 338:

| | Gate student | Baseline |
| --- | ---: | ---: |
| ROC AUC | 0.87 | 0.49 (source-family approval rate) |
| Accuracy | 84% | 74% (always reject) |
| Log loss | 0.37 | 0.58 |
| Decides alone at 95% confidence | 34% of items, 98.3% agreement | - |
| Decides alone at 90% confidence | 47% of items, 95.0% agreement | - |

Publish-leaning features: kill(s), strikes, hits. Reject-leaning: condemns, warns,
rejects, why. It is shadow only. Letting it skip Gemini for confident items would
cut review calls by roughly a third, but it needs the owner's decision and
human-graded evidence: agreement with the gate is not ground truth, and there are
still no human gate grades.
